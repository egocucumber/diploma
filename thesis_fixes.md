## 7. Раздел 3.2 — заменить полностью на:

```
3.2 Выбор и обоснование СУБД

В качестве системы управления базами данных выбрана PostgreSQL версии 15.
Выбор обусловлен следующими факторами:

1. Конкурентный доступ. Сервис обрабатывает запросы от нескольких
пользователей одновременно. PostgreSQL поддерживает MVCC
(Multi-Version Concurrency Control), что обеспечивает изоляцию
транзакций без блокировок на чтение.

2. Строгая типизация и ограничения целостности. Использование типов
SERIAL, TIMESTAMPTZ, REAL, TEXT и внешних ключей с ON DELETE CASCADE /
ON DELETE SET NULL гарантирует корректность реляционных связей между
таблицами users, sessions, analyses, results.

3. Масштабируемость. В отличие от файловых СУБД, PostgreSQL работает
как отдельный сервер, позволяя в будущем горизонтально масштабировать
приложение и подключать пул соединений (PgBouncer).

4. Интеграция с Docker. PostgreSQL запускается в отдельном контейнере
Docker Compose, что упрощает развёртывание и изолирует данные от кода
приложения.

Подключение выполняется через переменную окружения DATABASE_URL со
строкой DSN вида postgres://user:password@host:port/dbname?sslmode=disable.
Go-бэкенд использует драйвер lib/pq.
```

## 8. Раздел 2.3 — абзац про сбор данных (найти по первым словам и заменить)

**Найти (начало абзаца):** `Для формирования обучающей выборки`  
**Заменить всем абзацем:**

```
Для формирования обучающей выборки выполняется клонирование 13 открытых
репозиториев (Flask, Requests, FastAPI, HTTPx, Express, Axios, Lodash,
Gin, Mux, Echo, spring-petclinic, java-design-patterns и др.). Из истории
каждого репозитория извлекаются до 200 коммитов, содержащих изменения
исходного кода. Для каждого коммита формируется пара «до / после»
рефакторинга: исходный фрагмент (не более 200 токенов) и исправленный
фрагмент. Всего формируется до 150 пар на репозиторий.

Дополнительно реализован механизм tryCommitFix: если в истории коммитов
обнаруживается реальное исправление, соответствующее выявленному запаху
кода, и оно снижает цикломатическую сложность или количество параметров
функции — оно используется как ответ с повышенной уверенностью
(confidence = 0.92), минуя генерацию StarCoder2-3B.
```

## 9. Раздел 2.4 — добавить новый абзац про CodeBERT (после описания StarCoder2)

```
Модель детектирования запахов кода (CodeBERT)

Для задачи классификации запахов кода применяется дообученная модель на
основе microsoft/codebert-base (125 млн параметров). Модель распознаёт
15 классов: Long Method, Large Class, God Function, High Complexity,
Long Parameter List, Deep Nesting, Magic Numbers, Duplicate Code,
Dead Code, Commented-Out Code, Inconsistent Naming, Empty Catch Block,
Primitive Obsession, Feature Envy, Clean Code.

Обучение проводилось на 6 237 примерах кода из реальных репозиториев
на Python и Java с автоматической разметкой через статический AST-анализатор.
Для редких классов дополнительно сгенерированы синтетические примеры
(по 200 на класс). Применялся взвешенный кросс-энтропийный критерий.
Итоговое качество: weighted F1 = 0.66 при 5 эпохах обучения,
lr = 2×10⁻⁵, batch size = 16, max_length = 256 токенов.

В рабочем пайплайне CodeBERT выступает основным детектором: если модель
возвращает класс, отличный от «Clean Code» — результат передаётся в
генератор рефакторинга. Иначе активируется резервный статический анализатор
на основе AST и регулярных выражений.
```
